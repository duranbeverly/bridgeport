For VDIs and locked-down machines

When you can't install tools, can't connect outside services, and the list view hides the field you need, Bridgeport generates a console script instead. Paste it into the browser's DevTools on the Jira page. It uses your existing login, reads every matching test through Jira's own API (100 per page, no 1,000-row cap), and copies a clean table to your clipboard, ready to paste into Excel.

  • Read-only: it never changes anything in Jira.
  • Nothing leaves the machine: no outside servers, no extensions, no installs.
  • Works with Jira Cloud and Jira Server/Data Center.

  1. Open Jira (any page) where you're logged in. Press F12 and open the Console tab.
  2. If Jira shows an app in a frame (like Xray), set the Console's context dropdown (top-left) to top. The script checks this and tells you if it's wrong.

  5. Click cell A1 in Excel and press Ctrl+V. One test per row.

The problem

A QA team needed every test case in their Jira/Xray repository in one spreadsheet, with the full description, to review and plan coverage. It sounds like a simple export. It wasn't:

  • The list view hides descriptions. You have to click into each test, one at a time, across thousands of tests.
  • Exports stop at about 1,000 rows, so large repositories come out in overlapping chunks.
  • Multi-line descriptions break spreadsheets. One test spills across several rows.
  • The team works inside a locked-down VDI. No installs, no outside tools, strict security.

Design decisions

  • Use the API, not the screen. Scraping the list view can't see descriptions and breaks when the UI changes. Jira's search API returns every field, 100 tests per page, with no 1,000-row cap.
  • Zero-install by design. The VDI path is a single script that runs with the user's existing session, so there's no new credential, no new network path, and nothing to get approved.
  • Read-only and gentle. It only makes GET requests, with a short pause between pages.
  • Validate before you export. Missing descriptions, duplicate keys, empty fields, and text over Excel's cell limit are flagged, not silently dropped.
  • Spreadsheet-safe output. One line per test, real .xlsx output, and protection against cells being read as formulas.
